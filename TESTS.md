# Tests

How the test suite of nyuRuns is run, and what its fixtures and helpers hold.

## Running
- Run the suite with `php test/run.php`, or name groups: `php test/run.php unit audit`.
- Groups: `unit`, `audit` (naming conventions), `data`, `http`.
- The `data` and `http` groups need the `pdo_sqlite` extension; they are skipped when the extension is not loaded.
- The `http` group writes to the project's own `temp/logs`.
- The 2FA encryption needs the `openssl` extension; a command-line PHP without a php.ini loads it only when told (`-d extension=openssl`, or a `PHPRC` php.ini).

## Fixtures
- Route fixtures are in test/fixtures/routes, their files in test/fixtures/pages; the Probe application has its pages in test/fixtures/runs/Probe/pages.
- test/fixtures/runs/Shows is the example Run, generated by makerun from the sample tables (`shows`, with `events` and `items`); `RunGenTest` checks it is what makerun generates, and `RunSpecTest` checks the spec, the generator and the refusals.
- The users file fixture is test/fixtures/users.lst (password `pw-<name>`), its config in test/fixtures/confusr.
- Other fixtures: test/fixtures/confreq (a body of 1 KB and 2 parts at most), test/fixtures/errpages (error pages of a site).
- test/fixtures/confjwk: RS256 tokens with an issuer, an audience and a previous key; the HTTP test makes their keys in `temp/httpjwk`.
- The sample database (test/lib/sample.php) builds its `users` and `devices` tables from conf/schema (`users.sqlitedb.sql`, `devices.sqlitedb.sql`): the delivered schema is the one tested.

## Writing a test
- A test that reads logs plugs its own folder with `Logger::plugLogsConfig()` and unplugs it with `Logger::plugLogsConfig( Array() )`.
- test/lib/cacheChild.php runs one request through the Runner on a project folder of its own (`ConfigCacheTest`, `RouterTest` for a closed Run end to end, and `DoorwaysTest` for the map, given a host as its fourth argument); a test of its own checks a file another process removed after `clearstatcache()`.
- The descriptions of tables in the config cache are tested on two sample SQLite files (test/data/TableCacheTest.php).
- A test sending a wrong credential through the Checker with an address sets `'TRYLIMIT'=>Array('maxTries'=>0)` or its own folder, or it counts in the project's `temp/limits`.
- The native mail client is tested against a fake SMTP server run as a child process (test/lib/smtpChild.php), in the `unit` group.
- The access mails are tested through an `emlFiles` account in a folder of the test's own.
