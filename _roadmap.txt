

nyuRuns RoadMap : 
=================

Presets:		Review each file in conf/presets and harmonize keys 
				and available variables that each file can or should
				contain. These keys must then be defined in each of
				the preset files, using only variables available. 
				Perhaps some of these should be removed or added.

SysConf:		Create a base config file (system.ini) deployed with 
				each project. It will include core variables of error
				handling, logging, path configuration, maybe routing
				and applications restrictions or permissions.

Routing:		The router should allow a set of tool for HTML or
				static pages, to allow navigation or redirection.

Logging:		The logging class should be reviewed to ensure proper
				understanding. It should be made available to every
				app in runs. All important events should be traced in
				a log, especially removal of records, authentication
				of privileged users and file uploads.

Error Handle:	Errors and warning are now implemented. Yet, they are
				currently returned asid from the data response. When
				returning HTML, a helper could be created to display
				a stack trace, to increase readability. On debug mode
				that output (HTML + StackTable) couldbe the fallback
				when certain errors are displayed.

Authenticate:	Authentication should be reviewed and all different 
				mechanics should be tested and approved. A basic DB
				authentification could be implemented under "native"
				option. It would integrate user, password (hashed),
				token, activation, status and 2FA fields.
				
Authenticate:	More authentication mechanisms or "connectors" could
				be integrated, like SSO, LDAP, Certificates, Session,
				and so on. Each mechanism should be carefully revised
				before integrating it.
				
ClientReg : 	Done. It holds the address, host, agent, system and
				language of the client, whether it looks human, and
				its kind as a code (dsktop, mobile, tablet, aiagnt,
				crawlr, script, shadow). Apps read it through the
				request (getClient). The address is seen through the
				reverse proxies listed in system.ini (PRX_LIST).
				Left out: the browser name; the screen, which only
				the client can tell; forwarded scheme and host.
				
Response :		Done. It is passed to each app's actionset, which can
				set headers, reply with a file (Range requests are
				supported), and break or end the run at anytime with
				a full or partial response (endAction).
							
CLI : 			Nice to have, call the runner through a CLI script, 
				to be able to automate tasks, generate code and make 
				runs callable by command line.
							
	------------
		
		Data : 			Image, Sound, Document and sockets, to read 
						and write rich elements, or to establish 
						some network connections
						
		Parsers : 		Read several data types (DOM, XML, Office, ...)
		Savers : 		Write several data types (DOM, XML, Office, ...)
