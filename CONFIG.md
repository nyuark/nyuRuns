# Configuration

The configuration keys and codes of nyuRuns, the database naming, the presets and the routes.

## Keys and codes
- The `system.ini` keys are 8 characters in the `XXX_YYYY` form (`LOG_MODE`, `ERR_SHOW`, `PRX_LIST`, `DEF_ROWS`, `REQ_SIZE`); the values that are codes are 4 characters in upper case (`ENV_NAME` `DEVS` / `TEST` / `PREV` / `PROD`, `LOG_ROTA` `INDX` / `WEEK` / `MNTH` / `NONE`).
- Codes produced at run time are 8 characters too (e.g. the client kinds `computer` / `handheld` / `tabletPc` / `llmAgent` / `crawlers` / `scripted` / `shadowed`). A code that names a file (preset, mail kind, database type, bundle mode) is in lower case. Bundle modes are free of the 8-character rule: a mode is named freely, as an action is, and carries its environment as `ENV_NAME`.
- Route file keys are 8 characters (`mthdList`, `pointsTo`); so are the keys of a target block (`appToRun`, `doAction`, `redirect`, `httpCode`, `filePath`, `fldrPath`, `pageFile`).
- The route registry keys added by the Router are 8 characters (`routKind`, `routPath`, `routTarg`, `routStat`, `routType`, `routBase`); the route kinds are `toAction` / `redirect` / `toStatic` / `htmlPage`.
- The credential checks and carriers have 8-character codes (`htpasswd`, `nativeDb`, `regdKeys`, `userFile`, `dvcToken`; `httpBasc`, `apiHeadr`, `jwtToken`, `phpSessn`, `clntCert`); a block of `access.json` is named by its code, and its keys are 8 characters too.
- A file of `conf` that is not a config must not end in `.json` or `.ini`: the Loader reads them all (`access.json.dist`, `users.lst`, `bundle.lst`, `doorways.lst`).

## Database naming
- Database fields: every column name is 10 characters. The record identifier is `id_` followed by the singular table name (`users` -> `id_user`), whatever its length.
- A link to a record of another table is the identifier reversed: the singular table name followed by `_id` (`users` -> `user_id`), for one-to-many links, whatever its length.
- A link to a parent record of the same table is `parent_id`.
- The SQLite handler turns the foreign keys on for each connection, as the other databases have them.

## system.ini
- A config file that cannot be read (`system.ini`, `access.json`, `database.json`, `mailer.json`: a JSON or an ini the parser refuses) stops every request with a 500 `Configuration unreadable`: a site does not run on half a config. The log and the commands name it (`conf/<file> cannot be read: <reason>`), never the reply, and `install checkAll` fails the row `config files`, once per such file. A value holding `!` or another sign of the ini syntax is written between quotes.
- `LOG_PATH` is read from the project root, with or without a leading slash; `temp/logs` when not set.
- `LOG_MODE` decides the levels written: `MINI` errors, warnings and notices; `BASE` adds info; `FULL` adds debug and the context.
- `ERR_LEVL` is the level of the errors PHP reports (`Loader::errorConfigNum()`): `E_*` names joined by `|`, `&` and `~`, `&` before `|` as in PHP, read name by name and never run; written between quotes when it holds `&` or `~` (unquoted, the ini parser turns it into a number, which is read too); `E_ALL` when empty. A name that is not an error level stops the start-up with a 500, and fails `install checkAll` (`error level`). What the level leaves out is neither shown nor logged. The bundle modes write it (`E_ALL`), `bundles makeMode` asks it, `setting setValue` checks it.
- `REQ_SIZE` (KB) is the largest body read and `REQ_PART` the most parts of a multipart body sent with PUT or PATCH; beyond them the request is answered 413. 0 is no limit.
- `CNF_CACH` (`TRUE`/`FALSE`) caches the config: the first request of a preset writes `temp/cache/config-<preset>.cache` (the preset, the files of `conf` with their `env:` values as written, the routes), the next ones read it; `.env` is still read on each request. Anything a command writes in `conf` removes it, and so do `setting clrCache`, `install complete` and `cleanup cleanDir cacheDir`; after a hand edit of `conf`, `CNF_CACH` included, run `php nyuRun setting clrCache`. A request writes nothing when a config, preset or route file is newer than its start. `install checkAll` warns about a cache older than its files (`config cache`).
- `TBL_CACH` (`TRUE`/`FALSE`, with `CNF_CACH`) keeps the description of each table in that cache, by database (`SqlStore::tableInfoArray()`): no `EXPLAIN` on each request. A table changed outside nyuRuns (a migration, an `ALTER TABLE`) needs `php nyuRun setting clrCache`; a query failing on a table described from the cache removes the cache, and `install userBase` removes it too. `install checkAll` warns about `TBL_CACH` without `CNF_CACH` (`table cache`); `bundles` leaves it as the project sets it.
- `DEF_LANG` is the language of the mails of a user who has none: a tag in lower case (`en`, `fr`, `fr-ch`), `en` when not set. One that is not a tag fails `install checkAll` (`mail language`); `setting setValue` checks it.

## Presets and the map
- A preset holds `presetId`, `synopsis` and the blocks `settings` (`confType`, `confList`, `confPath`, `envrFile`), `security` (`required`, `carrWith`, `carrConf`, `authWith`, `authConf`, `openList`, `signPath`, `minRoles`, `appsConf`, `isPublic`), `inputSet` (a list of sources, each `sourceId`, `readFrom`, `fieldSet`), `dispatch` (`detectBy`, `pathForm`, `routeDir`, `fileRoot`, `runMount`: where the routes of each run are served, or `false`; `"*"` names every Run without a line of its own, so `statics` serves none (`"*": false`)) and `response`.
- `confType` and the `fieldSet` of a source are `all` when left out. A source without its `sourceId` or its `readFrom`, or a `confPath` naming a folder that is not there, stops the preset from loading: the request is answered 500, the log names the key, and `install checkAll` fails the row of the preset.
- A new key of a preset block is added to `Preset::KEYS_LIST`, or the preset does not load.
- The preset `example` (`Preset::XMPL_NAME`) only explains the keys of a preset: its keys are checked, it is never loaded. A line of the map or an entry point naming it is answered 500, `setting entryPts` and `install complete` refuse it, and `install checkAll` fails on it (`doorways`).
- `conf/doorways.lst` maps each request to a preset: `{ "doorways": [ { "hostName", "basePath", "presetId" } ] }`, `hostName` optional. A Runner built with no preset name reads it first (`Runner::pickPresetName()`): a line naming the host before a line without, then the longest `basePath`, matched by whole parts of the path; no map, an empty one or no line matching gives `default`, a map that cannot be read a 500. A Runner given a preset never reads it. The `basePath` is taken off the path before routing, kept as `routBase`, and put back in front of the links (`routLinkString`), the redirect routes and `signPath`. Read on each request, never cached. `setting entryPts [basePath] [preset]` (`--hostName`, `--removeIt`) lists, sets or removes a line; `install complete` asks it last (`/=default`, `/=statics` for an `openSite`).
- The `response` block of a preset can list the origins other sites may call from (`corsList`); `Access-Control-Allow-Origin` then names a listed origin only.
- The `outputAs` of a preset's `response` block is one of `jsonData` (default), `yamlData`, `xmlNodes`, `csvTable` (CSV of a list of records), `htmlView` (records in a table, other values in definition lists), `rawBytes` (a text or a Fluxd, sent as it is) (`Response::FORM_LIST`); an unknown one stops the preset from loading. With `csvTable` and `rawBytes`, an error is written as JSON and warnings stay in the log.
- An action writes its reply in another format with `useReplyFormat()`; with `rawBytes` it sets its own `Content-Type` (`application/octet-stream` otherwise).

## Routing
- A declared route's `pointsTo` names one kind: an action (`appToRun`, `doAction`), a redirection (`redirect`, `httpCode`), a static file (`filePath`) or folder (`fldrPath`), or an HTML page (`pageFile`); one block per method can mix kinds.
- A final `*` in a route path takes the rest of the path; it is how a `fldrPath` target gets its file.
- Static files and pages lie under the preset's `dispatch.fileRoot` folder; nothing is served without it.
- A file asked for in a folder can never leave it; only the extensions of `Response::TYPE_LIST` are served. Any refusal is the same 404.
- Page placeholders are `%name%`; values are always HTML-encoded. Pages and mails share the filler (`Template::fillNamedSlots()`).
- `openList` opens an action as `app/action` or `app/*`, or a declared route by its path with a leading slash (`/login`, `/assets/*`), exactly as declared; a folder route then opens every file of the folder.
- An error on a page or a static file is answered with `<fileRoot>/errors/<status>.html` when the site has one (`%code%`, `%error%`), and so is a path no route answers in a `manually` preset; an action keeps the preset's format.
- An application is named with letters and digits only, and found whatever its case: the Router, the Controller and the Checker share one resolver (`Controller::runFoldrString()`). Anything else is a 404, and so are two Run folders differing by their case alone, logged as an error on `runner`.
- Whatever the client cannot reach is the same 404 `Not Found`: an unknown application or action, a helper, an action closed by its route, a missing file or page, a role not held. The reason is logged on `runner` (the Controller checks `Actionset::hasActionNamed()` before creating the actionset); a default action naming none is a 500, logged as an error.
- A route limiting its methods (`mthdList`, or one target per method) limits that route only: its action stays reachable by its path unless its Run declares routes (a closed Run). Method limits are not an access control (HOSTING.md §13).
- A key of a route file that nothing reads is logged as a warning on `runner` (`Router::KEYS_LIST`, `Router::TRGT_KEYS`).
- Every reply carries `X-Content-Type-Options: nosniff`, whatever the preset writes.
- A static file is sent with `ETag`, `Last-Modified` and `Cache-Control: public|private, no-cache`, replacing the preset's cache headers; a client that holds it gets a 304.

## Tokens, keys and stores (access.json)
- `jwtToken` signs the tokens with `signAlgo` `HS256` (`hmacSecr`) or `RS256` (`privFile`, `publFile`: PEM files in `conf/keys`, ignored by git, made at 4096 bits by `setting mkSecret jwtToken`, refused under 2048). A block with `publFile` alone checks tokens and issues none: its login answers 501. RS256 tokens carry a `kid`, the RFC 7638 thumbprint of the public key. It names the `issuerId` and the audiences (`audience`, a text or a list) its tokens carry as `iss` and `aud`, both checked once set; `prevFile` is the previous public key, still checking the tokens it signed (`setting mkSecret jwtToken` keeps it as `conf/keys/<block>.old.pub`). The RS256 keys of the login are published at `/.well-known/jwks.json` (`auth/keyset`), a 404 with HS256. `"external": true` says a `publFile` alone is the key of another server: `install complete` keeps it and makes no pair, and `install checkAll` doesn't ask for its private key.
- The 2FA secrets are stored encrypted with the `tfaCrypt` of the store's block (`nativeDb`, `userFile`), 32 characters at least; readable, with a warning, without one.
- A `keysList` is a plain list of API keys, or the keys by the name of their holder, which then identifies it.
- The `appsKeys` block of `access.json` holds the keys of the applications calling for their users: `headName` (`X-App-Key` when not set) and `appsList`, each application by its name with `keyDigst` (SHA-256 hash of its key), `routeSet`, `publFile`, `roleTops`, `madeDate`. A preset reads it when its `security` block names it under `appsConf`, and `audience`, the audiences naming this project: once set, an application's token names them and its `issuerId` (the name of the application when its entry gives none).
- The `nativeDb` block sends the access mails when `mailAcnt` names an account of `mailer.json`; `signupOn` (true) opens the sign-ups, `codeMins` is the minutes a mailed code lasts (15), `linkTmpl` the front-end link (`%mailKind%`, `%userName%`, `%sentCode%`; the mail templates keep their own `%user%`, `%code%`). Without `mailAcnt`, the codes are given in the replies.

## Tables delivered (conf/schema)
- Every date of `users` and `devices` is written by the clock of PHP, in its time zone (`date.timezone`), `createDate` too; its `DEFAULT CURRENT_TIMESTAMP` only serves a row written by hand, in the time of the database.
- The `users` table holds `twoFactPos`, the step of the last 2FA code accepted: a code is accepted once.
- The `users` table holds `twoFactWay` (`emailOtp`: a code mailed at each login, set by `account setTwoFa <user> --emailOtp`), `twoFactHsh` (hash of that code) and `twoFactExp` (its end); one mail a minute at most, none for a Basic header. Native userbase only: a move to the users file is refused while a user has them. A table already at 1.0 needs the lines at the end of `migrate-users-1.0.<type>.sql`.
- The `users` table holds `contactEml` (lower case, one account each), `userLocale` (the language of its mails, a tag in lower case, the default one when empty), `recovrCode` (hash of a reset asked by the user), `codeExpiry` (end of the code in use) and `signupDate` (a sign-up not yet approved); the statuses are `awaiting`, `inReview`, `approved`, `disabled`; the roles (`accessRole`) `standard`, `advanced`, `delegate`, `managers`. A table of 0.9 is moved by `migrate-users-1.0.<type>.sql`; one made by an earlier copy of 1.0 runs only the lines at its end (`userHandle`, `twoFactStp`, `failedDate`, `mailboxAdr`, `mailedCode`, `mailExpiry` renamed `systemName`, `twoFactPos`, `failedTime`, `contactEml`, `twoFactHsh`, `twoFactExp`; the status `checking` made `inReview`; the roles `internal`, `operator`, `sysadmin` made `standard`, `advanced`, `managers`).
- The `devices` table holds `id_device`, `deviceName`, `deviceRole`, `deviceTops` (the cap: the highest role the device acts with, one of the four roles; empty only for a device made before it, added to an existing table by the last statement of `migrate-devices-1.0.<type>.sql`), `bearerHash` (SHA-256 hash of the token), `user_id`, `accessDate`, `revokeDate`, `createDate`; the devices of a removed user are removed with it (`ON DELETE CASCADE`).

## Mail accounts (mailer.json)
- The accounts of `mailer.json` have 8-character keys (`sendWith`, `hostName`, `portNumb`, `userName`, `passWord`, `fromAddr`, `fromName`, `waitSecs`, `mailsDir`, `copiesTo`); the first one is the default. Types: `selfSmtp` (text and HTML, no attachment), `phpMailr` (PHPMailer, suggested, not required), `emlFiles` (writes `.eml` files in `mailsDir`, `temp/mails` when not set).
- The encryption of a mail follows the port: 465 is TLS from the first byte, any other port needs STARTTLS; only a server on this machine is spoken to unencrypted. Certificates are always verified.
- A `copiesTo` sends every mail again, as it is and separately, to its addresses; a copy that fails is logged only.
